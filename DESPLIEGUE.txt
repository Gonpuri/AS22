PASO A PASO PARA DESPLEGAR EL SISTEMA ESCOLAR (AS22)
====================================================

Arquitectura de producción:
  - Base de datos PostgreSQL ........ Render
  - API (Django REST Framework + FastAPI, una sola app ASGI) ... Koyeb
  - Frontend (Vue + TypeScript + Vuetify) ... Vercel

Repositorio: https://github.com/Gonpuri/AS22  (privado, rama main)

Orden obligatorio:
  1) Base de datos en Render   2) API en Koyeb   3) Frontend en Vercel
  4) Volver a Koyeb para habilitar el origen del frontend (CORS)
  5) Crear el administrador   6) Verificar


-------------------------------------------------------------------------------
1. BASE DE DATOS POSTGRESQL EN RENDER
-------------------------------------------------------------------------------
  1.1  https://dashboard.render.com -> "New +" -> "Blueprint" -> elegir el repositorio
       AS22. Render lee render.yaml y crea solo la base "escuela-db".
       (Alternativa manual: "New +" -> "PostgreSQL", nombre escuela-db, base "escuela",
       usuario "escuela", plan Free.)

  1.2  Cuando la base figure "Available", abrirla -> "Connections" -> copiar la
       "External Database URL" (empieza con postgresql://...).
       IMPORTANTE: Koyeb está fuera de Render, así que NO sirve la "Internal Database URL".

  1.3  Agregar al final de esa URL el parámetro de seguridad:
           ?sslmode=require
       Ejemplo:
           postgresql://escuela:CLAVE@dpg-xxxx.oregon-postgres.render.com/escuela?sslmode=require

       Esta URL contiene la contraseña de la base: tratarla como secreta (no subirla a
       GitHub, no pegarla en chats ni capturas). Se usa en el paso 2.4 y en el paso 5.

  Nota: la base gratuita de Render tiene vencimiento y límites; verificar las condiciones
  vigentes en render.com/pricing y pasar a un plan pago si el uso va a ser permanente.


-------------------------------------------------------------------------------
2. API EN KOYEB
-------------------------------------------------------------------------------
  2.1  Crear cuenta en https://app.koyeb.com (se puede ingresar con GitHub).

  2.2  "Create Service" -> "Web Service" -> fuente "GitHub".
       Instalar/autorizar la app de Koyeb en GitHub y darle acceso al repositorio AS22
       (al ser privado, hay que concederlo de forma explícita).

  2.3  Configurar el build:
           Repository ........ Gonpuri/AS22
           Branch ............ main
           Work directory .... backend
           Builder ........... Dockerfile   (usa backend/Dockerfile)
           Dockerfile location  Dockerfile  (por defecto)

  2.4  Variables de entorno ("Environment variables"):
           DATABASE_URL           la URL del paso 1.3 (marcarla como Secret)
           DJANGO_SECRET_KEY      una cadena larga y aleatoria (marcarla como Secret).
                                  Para generarla, en PowerShell:
                                    python -c "import secrets; print(secrets.token_urlsafe(50))"
           DJANGO_ALLOWED_HOSTS   el dominio que Koyeb asigna al servicio, SIN https://
                                  y sin barra final. Ejemplo: as22-api-micuenta.koyeb.app
                                  (ver nota abajo si todavía no lo conocés)
           CORS_ALLOWED_ORIGINS   por ahora  http://localhost:5173  (se corrige en el paso 4)
       No definir DJANGO_DEBUG: en producción queda desactivado.

  2.5  Puerto y chequeo de salud:
           Puerto expuesto ... 8000, protocolo HTTP, ruta "/"
           (el contenedor usa la variable PORT que define Koyeb; 8000 por defecto)
           Health check ...... HTTP, ruta  /api/docs   (responde 200 sin login)

  2.6  Instancia: elegir la gratuita (Free / Eco) o la que corresponda según el plan
       vigente de Koyeb. Región: la más cercana a la base de Render (por ejemplo, USA
       si la base está en Oregon/Ohio). Ponerle un nombre al servicio, por ejemplo
       "as22-api", y pulsar "Deploy".

  2.7  Koyeb construye la imagen y la inicia. En cada arranque el contenedor ejecuta
       "python manage.py migrate", así que las tablas se crean solas en la base.

  2.8  Al terminar, anotar la URL pública del servicio, por ejemplo:
           https://as22-api-micuenta.koyeb.app
       NOTA sobre ALLOWED_HOSTS: el dominio exacto se muestra en el panel del servicio.
       Si lo supiste recién ahora, volver a "Settings" -> "Environment variables",
       corregir DJANGO_ALLOWED_HOSTS y redesplegar.

  2.9  Probar en el navegador:   https://TU-API.koyeb.app/api/docs
       Debe abrir la documentación de FastAPI. Los demás endpoints piden login.


-------------------------------------------------------------------------------
3. FRONTEND EN VERCEL
-------------------------------------------------------------------------------
  3.1  https://vercel.com/new -> importar el repositorio AS22 (autorizar el acceso a
       repositorios privados si lo pide).

  3.2  Configurar:
           Framework Preset ....... Vite   (se detecta solo)
           Root Directory ......... frontend      <-- IMPORTANTE, cambiarlo
           Build Command / Output . ya vienen definidos en frontend/vercel.json

  3.3  Variable de entorno:
           VITE_API_URL = https://TU-API.koyeb.app     (URL del paso 2.8, sin barra final)
       Se incorpora al construir el frontend: si se cambia, hay que redesplegar.

  3.4  "Deploy". Anotar la URL del frontend, por ejemplo https://as22.vercel.app


-------------------------------------------------------------------------------
4. HABILITAR EL FRONTEND EN LA API (CORS)
-------------------------------------------------------------------------------
Sin este paso el navegador bloquea las llamadas del frontend a la API.

  4.1  Koyeb -> servicio -> "Settings" -> "Environment variables".
  4.2  Editar CORS_ALLOWED_ORIGINS con la URL exacta de Vercel, sin barra final:
           https://as22.vercel.app
       Varios orígenes: separarlos con coma, sin espacios.
  4.3  Guardar y redesplegar el servicio.


-------------------------------------------------------------------------------
5. CREAR EL PRIMER ADMINISTRADOR
-------------------------------------------------------------------------------
La base nueva no tiene usuarios. Se crea el primero desde tu computadora, apuntando a
la base de Render.

  5.1  En PowerShell, dentro de la carpeta backend\ :

           .venv\Scripts\activate
           $env:DATABASE_URL = "PEGAR_AQUI_LA_URL_DEL_PASO_1.3"
           python manage.py migrate
           python manage.py createsuperuser

       (El "migrate" es seguro aunque Koyeb ya lo haya ejecutado.)
       Ingresar usuario, email (opcional) y contraseña.

  5.2  Limpiar la variable para no dejar la terminal apuntando a producción:
           Remove-Item Env:DATABASE_URL

  Si el entorno virtual no existe en esa computadora:
           python -m venv .venv
           .venv\Scripts\activate
           pip install -r requirements.txt


-------------------------------------------------------------------------------
6. VERIFICACIÓN FINAL
-------------------------------------------------------------------------------
  6.1  Abrir la URL de Vercel e ingresar con el administrador del paso 5.
  6.2  Recorrer el orden natural de carga:
           a) Estructura académica: Orientaciones, Años, Divisiones, Materias.
           b) Horarios.
           c) Recursos humanos: Personal -> Designaciones -> Cursos y materias.
           d) Administración -> Usuarios (alta de los demás usuarios).


-------------------------------------------------------------------------------
7. ACTUALIZAR LA APLICACIÓN DESPUÉS
-------------------------------------------------------------------------------
  - Cada "git push" a main redespliega solo en Koyeb y en Vercel.
  - Las migraciones se aplican en cada arranque de la API.
  - Antes de subir cambios, correr las pruebas:
           backend:   cd backend ; .venv\Scripts\activate ; pytest
           frontend:  cd frontend ; npm test ; npm run build


-------------------------------------------------------------------------------
PROBLEMAS FRECUENTES
-------------------------------------------------------------------------------
  * El build de Koyeb falla
        -> Revisar que "Work directory" sea  backend  y el Builder  Dockerfile.
           Ver el log del build en el panel del servicio.

  * El servicio queda "Unhealthy" / reinicia
        -> Mirar los "Runtime logs". Causas típicas: DATABASE_URL incorrecta (se usó
           la Internal en vez de la External, o falta ?sslmode=require), o el puerto
           expuesto no coincide con el de la variable PORT.

  * "Bad Request (400)" al llamar a la API
        -> DJANGO_ALLOWED_HOSTS no incluye el dominio real de Koyeb (paso 2.8).

  * "No se pudo conectar con el servidor" en el login
        -> VITE_API_URL incorrecta o sin redesplegar el frontend (paso 3.3), o
           CORS_ALLOWED_ORIGINS no coincide exactamente con la URL de Vercel (paso 4).
           En la consola del navegador (F12) aparece un error de CORS.

  * Primera carga lenta
        -> Las instancias gratuitas pueden dormirse por inactividad; es esperable.

  * Recargar una pantalla en Vercel da 404
        -> Verificar que frontend/vercel.json esté en el repositorio.

  * Olvidé la contraseña del administrador
        -> Repetir el paso 5 con:  python manage.py changepassword NOMBRE_DE_USUARIO
