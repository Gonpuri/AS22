PASO A PASO PARA DESPLEGAR EL SISTEMA ESCOLAR (AS22)
====================================================

Arquitectura de producción:
  - Base de datos PostgreSQL ................ Render
  - API (Django REST Framework + FastAPI) ... Render   (una sola app ASGI)
  - Frontend (Vue + TypeScript + Vuetify) ... Vercel

Repositorio: https://github.com/Gonpuri/AS22   (privado, rama main)

Orden obligatorio:
  1) Render (base + API)   2) Vercel (frontend)   3) Volver a Render para habilitar
  el frontend (CORS)   4) Crear el administrador   5) Verificar

Archivos de configuración que ya están en el repositorio (no hay que crearlos):
  render.yaml ............ base de datos + servicio web de la API
  frontend/vercel.json ... build del frontend y reescritura de rutas (SPA)


-------------------------------------------------------------------------------
0. REQUISITOS
-------------------------------------------------------------------------------
  - Cuentas en GitHub, Render (render.com) y Vercel (vercel.com). En Render y Vercel
    se puede ingresar con la cuenta de GitHub.
  - Como el repositorio es privado, al conectar Render y Vercel hay que concederles
    acceso al repositorio AS22 (la pantalla de autorización de GitHub lo pide).
  - Para el paso 4 (crear el administrador): Python 3.14 en tu computadora.


-------------------------------------------------------------------------------
1. RENDER: BASE DE DATOS + API
-------------------------------------------------------------------------------
render.yaml crea los dos recursos juntos:
  - Base PostgreSQL "escuela-db" (plan free).
  - Servicio web "escuela-api" (plan free, Python 3.14.8, directorio backend).

  1.1  https://dashboard.render.com -> "New +" -> "Blueprint".

  1.2  Conectar GitHub y elegir el repositorio AS22. Render lee render.yaml y lista
       los recursos que va a crear.

  1.3  Render pide el valor de la variable marcada "sync: false":
           CORS_ALLOWED_ORIGINS  -> por ahora poner  http://localhost:5173
                                    (se corrige en el paso 3)

  1.4  "Apply" / "Deploy Blueprint". Render ejecuta, en este orden:
           pip install -r requirements.txt
           python manage.py collectstatic --noinput
           python manage.py migrate                 (crea las tablas en la base)
       y luego inicia la API con uvicorn en el puerto que asigna Render.

  1.5  Esperar a que "escuela-api" figure como "Live". Anotar su URL pública, por ejemplo:
           https://escuela-api.onrender.com
       (puede ser otra si el nombre ya estaba en uso: usar la que muestra Render).

  1.6  Probar en el navegador:   https://TU-API.onrender.com/api/docs
       Debe abrir la documentación de FastAPI. Los demás endpoints piden login.

  Qué configura Render automáticamente (no hay que tocarlo):
    DATABASE_URL ............ se toma de la base (red interna de Render)
    DJANGO_SECRET_KEY ....... se genera sola; no compartirla
    RENDER_EXTERNAL_HOSTNAME  la define Render; la aplicación la usa como dominio permitido
    PYTHON_VERSION .......... 3.14.8 (fijada en render.yaml)

  Plan gratuito: el servicio web se "duerme" tras un rato sin uso y la primera petición
  tarda en responder. La base gratuita tiene vencimiento y límites: verificar las
  condiciones vigentes en render.com/pricing y pasar a un plan pago si el uso va a ser
  permanente.


-------------------------------------------------------------------------------
2. VERCEL: FRONTEND
-------------------------------------------------------------------------------
  2.1  https://vercel.com/new -> importar el repositorio AS22.

  2.2  Configurar:
           Framework Preset ....... Vite   (se detecta solo)
           Root Directory ......... frontend      <-- IMPORTANTE, cambiarlo
           Build Command / Output . ya vienen definidos en frontend/vercel.json
           Node.js ................ 20.19 o superior (declarado en package.json)

  2.3  En "Environment Variables" agregar:
           Nombre:  VITE_API_URL
           Valor:   https://TU-API.onrender.com        (URL del paso 1.5, SIN barra final)
       Se incorpora al construir el frontend: si se cambia después, hay que redesplegar.

  2.4  "Deploy". Anotar la URL del frontend, por ejemplo  https://as22.vercel.app


-------------------------------------------------------------------------------
3. HABILITAR EL FRONTEND EN LA API (CORS)
-------------------------------------------------------------------------------
Sin este paso el navegador bloquea las llamadas del frontend a la API.

  3.1  Render -> servicio "escuela-api" -> "Environment".
  3.2  Editar CORS_ALLOWED_ORIGINS con la URL exacta de Vercel, sin barra final:
           https://as22.vercel.app
       Varios orígenes: separarlos con coma, sin espacios.
  3.3  Guardar. Render redespliega automáticamente.

  Nota: cada despliegue "preview" de Vercel tiene una URL distinta; solo el dominio
  agregado en CORS_ALLOWED_ORIGINS podrá usar la API.


-------------------------------------------------------------------------------
4. CREAR EL PRIMER ADMINISTRADOR
-------------------------------------------------------------------------------
La base nueva no tiene usuarios, y sin uno no se puede ingresar al sistema. El administrador
se crea solo en cada despliegue de Render (comando "crear_admin" del buildCommand) a partir
de dos variables de entorno. Si el usuario ya existe no se toca, y su contraseña nunca se
sobrescribe.

  4.1  Render -> servicio "escuela-api" -> "Environment" y definir:
           ADMIN_USERNAME   el nombre de usuario (render.yaml propone "admin")
           ADMIN_PASSWORD   una contraseña segura (mínimo 8 caracteres)

  4.2  "Manual Deploy" -> "Deploy latest commit". En el log del build debe aparecer:
           Administrador 'admin' creado.

  4.3  Ingresar al frontend con ese usuario y contraseña.

  4.4  Para dar de alta a las demás personas usar Administración -> Usuarios. Después de
       entrar por primera vez conviene borrar ADMIN_PASSWORD del panel de Render (el
       usuario ya quedó creado y la contraseña no se vuelve a usar).

  Para cambiar la contraseña del administrador: hacerlo desde Administración -> Usuarios
  (editar el usuario). Cambiar ADMIN_PASSWORD no la modifica.

  Alternativa manual (desde tu PC, con la External Database URL de la base en Render):
           cd backend ; .venv\Scripts\activate
           $env:DATABASE_URL = "PEGAR_AQUI_LA_EXTERNAL_URL"     (agregar ?sslmode=require si lo pide)
           python manage.py createsuperuser
           Remove-Item Env:DATABASE_URL


-------------------------------------------------------------------------------
5. VERIFICACIÓN FINAL
-------------------------------------------------------------------------------
  5.1  Abrir la URL de Vercel e ingresar con ADMIN_USERNAME / ADMIN_PASSWORD (paso 4).
       (La primera vez puede demorar si la API estaba dormida.)
  5.2  Orden natural de carga:
           a) Estructura académica: Orientaciones, Años, Divisiones, Materias.
           b) Horarios.
           c) Recursos humanos: Personal -> Designaciones -> Cursos y materias.
           d) Administración -> Usuarios (alta de los demás usuarios).


-------------------------------------------------------------------------------
6. ACTUALIZAR LA APLICACIÓN DESPUÉS
-------------------------------------------------------------------------------
  - Cada "git push" a main redespliega solo en Render y en Vercel.
  - Las migraciones se aplican en cada despliegue de Render (están en el buildCommand).
  - Antes de subir cambios, correr las pruebas:
           backend:   cd backend ; .venv\Scripts\activate ; pytest
           frontend:  cd frontend ; npm test ; npm run build


-------------------------------------------------------------------------------
PROBLEMAS FRECUENTES
-------------------------------------------------------------------------------
  * "No se pudo conectar con el servidor" en el login
        -> VITE_API_URL incorrecta o sin redesplegar el frontend (paso 2.3), o
           CORS_ALLOWED_ORIGINS no coincide exactamente con la URL de Vercel (paso 3).
           En la consola del navegador (F12) aparece un error de CORS.

  * "Bad Request (400)" al llamar a la API
        -> El dominio no está permitido. En Render la aplicación toma el dominio de
           RENDER_EXTERNAL_HOSTNAME; si usás un dominio propio, agregarlo en la
           variable DJANGO_ALLOWED_HOSTS (separado por comas).

  * Error 500 o el servicio no arranca
        -> Render -> servicio -> "Logs". Causas típicas: migración fallida o variable
           de entorno faltante.

  * El Blueprint cobra un plan pago
        -> Verificar que en render.yaml el servicio tenga  plan: free.

  * Primera carga lenta
        -> El plan gratuito de Render duerme el servicio; es esperable.

  * Recargar una pantalla en Vercel da 404
        -> Verificar que frontend/vercel.json esté en el repositorio.

  * El login pide usuario y no tengo ninguno
        -> Falta crear el administrador: ver paso 4 (ADMIN_USERNAME y ADMIN_PASSWORD en Render
           y redesplegar).

  * Olvidé la contraseña del administrador
        -> Desde tu PC, con DATABASE_URL apuntando a la base de Render:
           python manage.py changepassword NOMBRE_DE_USUARIO


-------------------------------------------------------------------------------
RESUMEN DE VARIABLES DE ENTORNO
-------------------------------------------------------------------------------
  Render (API) - editables en el panel:
      CORS_ALLOWED_ORIGINS   URL del frontend en Vercel, sin barra final   (obligatoria)
      DJANGO_ALLOWED_HOSTS   solo si se usa un dominio propio (opcional)
      ADMIN_USERNAME         usuario del administrador inicial                      (paso 4)
      ADMIN_PASSWORD         su contraseña; se puede borrar después del primer ingreso
      DATABASE_URL, DJANGO_SECRET_KEY, PYTHON_VERSION: ya definidas por render.yaml
      (DJANGO_DEBUG no se define: en producción queda desactivado)

  Vercel (frontend):
      VITE_API_URL           URL de la API en Render, sin barra final
